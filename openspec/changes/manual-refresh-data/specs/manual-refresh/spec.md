## ADDED Requirements

### Requirement: 用户可以刷新当前页面数据

Web 应用 MUST 在共享布局顶部提供当前页面数据的手动刷新入口。刷新 MUST 只调用当前路由注册的页面刷新动作，不改变用户当前的筛选、分页、Tab、详情标的或本地假设。

#### Scenario: 用户刷新列表页

- **假定**：用户位于可转债、LOF、封闭式基金或港股 IPO 列表页。
- **当**：用户点击共享布局中的刷新按钮。
- **则**：当前列表页重新读取其数据，并保持当前页面上下文。

#### Scenario: 用户刷新详情页

- **假定**：用户位于某个可转债、LOF 或港股 IPO 详情页。
- **当**：用户点击共享布局中的刷新按钮。
- **则**：当前详情标的重新读取，不跳转到列表页。

### Requirement: 刷新状态必须可观察

刷新进行中时，按钮 MUST 显示加载态并禁止重复触发；请求成功后 MUST 更新共享更新时间，失败时 MUST 保留已有数据并向用户报告失败。

#### Scenario: 刷新进行中

- **假定**：当前页面已经注册刷新动作。
- **当**：刷新请求尚未完成。
- **则**：刷新按钮显示加载态且不能再次发起同一页面刷新。

#### Scenario: 刷新失败

- **假定**：服务端强制刷新请求失败，且页面已有数据。
- **当**：刷新动作结束。
- **则**：已有数据继续显示，并向用户显示失败反馈，不把失败时间标记为新的数据更新时间。

### Requirement: 手动刷新请求必须要求服务端强制读取

业务 API 封装在手动刷新时 MUST 向支持该能力的读取端点传递 `refresh=true`；服务端仍以规范化响应信封返回数据和元数据。客户端 MUST NOT 把强制刷新解释为上游一定已有更新。

#### Scenario: 强制刷新列表数据

- **假定**：用户手动刷新一个支持强制读取的列表页。
- **当**：页面发起 API 请求。
- **则**：请求查询参数包含 `refresh=true`，并按服务端返回结果更新时间。

#### Scenario: 强制刷新没有产生新数据

- **假定**：上游数据在两次请求之间没有变化。
- **当**：强制刷新成功返回。
- **则**：页面可以显示相同数据，并继续披露服务端返回的缓存或来源状态。
