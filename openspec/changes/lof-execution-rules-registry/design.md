# 设计

## 契约消费

前端消费服务端 `execution.settlement_timing` 与新增 `execution.minimum_order`。时效对象仍使用既有键 `subscription_confirmation` 和 `redemption_payment`，但展示文案限定为场内申购确认和场内赎回到账。前端将其当作显示事实，绝不根据交易所、行情、其他基金或默认值计算 T+n。

最低申/赎分别包含状态、数值、单位、显示文本和来源。前端保留服务端的显示文本，不能把金额与份额换算。缺失字段显示 `--`。

## 展示

桌面表格保持现有“申/赎时效”列，显示两行 `申 T+n`、`赎 T+n`；新增相邻的“最低申/赎”列，显示两行 `申 100 元`、`赎 100 份`。列使用稳定宽度，避免内容变化造成表格抖动。

移动卡片将时效和最低申/赎作为相邻规则指标展示。详情页的申购与交割区域展示两类最低门槛以及服务端已有的时效来源链接、生效日期和核验时间。静态规则存在而状态待核验时，规则仍显示，现有策略状态继续保持观察。

## 验证

- Store/工具函数覆盖完整、部分缺失和旧响应。
- 组件测试验证桌面两列、移动规则块和详情原始单位。
- 浏览器在桌面与移动视口验证文字不重叠、缺失显示与详情链接。
