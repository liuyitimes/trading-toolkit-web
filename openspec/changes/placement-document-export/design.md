## 背景

配债工作区已经会规范化待发 API 行、按用户选择的预期上市溢价假设计算指标，并在页面内打开详情弹窗。它尚未保留逐候选标的发行人来源信息，也没有文档导出路径。服务端负责采集来源，必须实现同名配套变更；本仓库负责向后兼容的客户端契约、Markdown 生成和下载控件。

## 目标与非目标

**目标：**

- 为每个可见 Placement Candidate 导出可追溯的 Markdown 决策记录。
- 让导出指标与列表当前生效的溢价假设完全一致。
- 保留未核验、需复核和数据缺失之间的差异。
- 消费可选的逐候选标的来源信息，不破坏旧待发响应。

**非目标：**

- 批量选择、ZIP 生成、服务端文件生成、浏览器持久化或导出历史。
- 在 Web 中新增数据源采集、来源排序或投资执行行为。
- 推断缺失证据，或把规划观察表述为已核验收益。

## 决策

### 在浏览器生成 Markdown

从规范化候选详情生成 Blob，并直接触发单文件下载。这能保留当前客户端假设，无需服务端重复实现派生计算。

`placementExport` 仅承载无副作用的文件名和 Markdown 计算；浏览器下载由独立基础设施工具封装，`convertible` store 协调当前候选标的与快照元数据。视图只触发 store 操作，避免直接依赖浏览器能力。

备选方案是服务端导出接口。因其需要接收并重现用户选择的假设、引入临时文件生命周期问题，并为页面已有的数据增加一次不必要请求，故不采用。

### 使用显式逐项导出控件

在桌面表格增加专用操作列，在每张移动卡片增加对应操作。停止事件冒泡，确保导出不打开现有详情弹窗；使用项目既有图标库和无障碍标签。

备选方案是仅从详情弹窗导出。用户要求每项直接操作，且该方案会增加不必要的导航步骤，故不采用。

### 证据不可用时仍允许导出

文档设有来源证据和快照状态区块。缺失值显示为不可用，未核验和需复核状态保持可见。这符合现有配债观察要求，也保留了离线复核所需记录。

备选方案是证据核验前禁用导出。它会隐藏可见的规划观察，也阻止用户保存待核实事项，故不采用。

### 兼容地扩展现有待发响应

服务端配套变更为每个待发项增加可选来源对象。Web 在规范化时保留该对象并传入文档生成器。对象缺失时，数组和 `{ items, meta }` 响应形式依然有效。

备选方案是独立的来源或导出接口。导出基于当前展示的候选项，额外请求会引入延迟和数据不一致风险，故不采用。

## 风险与权衡

- [服务端配套变更尚不可用] -> Web 支持旧响应，并将候选标的来源显示为不可用。
- [浏览器下载限制或文件名非法] -> 只在明确逐项点击后生成一个文件，并且仅替换文件系统禁止的字符。
- [陈旧或未核验记录被误解为可执行机会] -> 每份文档均包含固定规划观察提示、新鲜度、核验和复核状态。
- [Markdown 与视图格式漂移] -> 从规范化详情和现有成本计算构建文档，并以聚焦测试覆盖其区块。

## 迁移计划

1. 在服务仓库落地同名 `placement-document-export` 变更，在保持当前待发响应形式的前提下增加可选逐候选标的来源字段。
2. 部署 Web 变更；增强响应自动展示来源，旧响应继续导出且缺失字段显式标注为不可用。
3. 回滚时移除导出控件和客户端工具；无需迁移存储数据，也无需清理服务端生成物。

## 待决问题

无。服务端和 Web 实现必须使用相同变更名，并在实现前对可选来源字段名达成一致。
