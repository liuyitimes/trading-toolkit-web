# 全站名言弹幕

Status: ready-for-agent

## 问题陈述

用户在名言管理中维护的名言目前仅在首页以固定顺序的跑马灯展示。浏览其他行情和管理页面时，用户看不到这些名言；首页展示也会一次循环全部内容，无法形成随机、轻量的弹幕体验。用户希望名言弹幕在不影响交易研究、表格操作和表单输入的前提下，随机选取两三条飘过整个 Web 应用。

## 解决方案

在桌面端共享布局的页头和可滚动内容区之间提供名言弹幕。它从当前名言列表中随机组成不重复的 2 至 3 条单行批次，并以约定节奏依次播放。弹幕拥有独立布局空间，普通区域点击穿透，唯一的可交互区域是关闭图标。

弹幕在窄屏和系统减少动态效果模式下隐藏。用户关闭后，在本次应用运行期内的所有路由保持隐藏，刷新页面后恢复默认显示。名言管理变更不打断当前批次，而是在下一批中反映。

## 用户故事

1. 作为桌面端用户，我希望在所有受支持页面看到名言弹幕，以便在浏览不同研究功能时都能获得一致的轻量展示体验。
2. 作为桌面端用户，我希望每次进入页面或切换路由时看到随机的两三条名言，以便避免反复阅读固定顺序的完整列表。
3. 作为桌面端用户，我希望同一批名言不重复，以便每一轮展示保持有效信息密度。
4. 作为名言较少的用户，我希望列表不足三条时只展示已有名言，以便不会因补足数量而看到重复文本。
5. 作为行情研究用户，我希望弹幕不遮挡或截获表格、按钮、输入框、弹窗和浮动工具的操作，以便持续完成分析和管理工作。
6. 作为阅读较长名言的用户，我希望名言在单一轨道中以稳定节奏依次经过，以便有足够时间阅读而不被多行动画干扰。
7. 作为对动态效果敏感的用户，我希望系统启用减少动态效果时自动隐藏弹幕，以便应用符合我的辅助功能偏好。
8. 作为移动端用户，我希望小屏幕不显示弹幕，以便有限的内容区不因装饰性信息而缩窄。
9. 作为暂时不想看到弹幕的用户，我希望能通过关闭图标隐藏它，以便当前浏览不被动态内容打扰。
10. 作为已关闭弹幕的用户，我希望在本次应用运行期的路由切换后仍保持关闭，以便不必重复关闭。
11. 作为重新加载应用的用户，我希望刷新后恢复默认展示，以便临时关闭不会成为难以发现的永久偏好。
12. 作为名言管理用户，我希望添加、编辑、删除或恢复默认名言后，已开始的当前批次能完整播放，以便内容不会在阅读中途跳变。
13. 作为名言管理用户，我希望下一批使用刚刚保存的名言列表，以便不必刷新页面也能看到管理结果。
14. 作为键盘和辅助技术用户，我希望关闭图标具有中文可访问名称，以便能识别并操作该控件。
15. 作为维护者，我希望关闭弹幕不修改名言列表，以便展示偏好与名言内容保持独立。

## 实施决策

- 采用现有的名言弹幕术语：它是从用户维护的名言列表中随机抽取并横向展示的非阻断式内容，不能妨碍页面主要操作。
- 弹幕仅在桌面端显示，位于共享页头与可滚动内容区之间，并占用独立高度。窄屏阈值为最大宽度 768px。
- 普通弹幕区域必须点击穿透。由于悬停暂停与完全点击穿透在浏览器事件模型中互斥，不提供悬停暂停；右侧图标关闭按钮是唯一接收指针事件的区域。
- 弹幕在首次加载和每次路由切换时生成一批；但名言管理变更已发生且当前批次尚未完成时，路由切换不得中断该批次，直到下一批才使用更新后的列表。名言列表不少于三条时随机选择两条或三条且不重复；少于三条时全量选择且不重复。
- 一批名言使用单行轨道从右向左连续播放 40 秒；批次结束后留出 4 秒空档，再使用当前可用列表生成下一批。
- 名言数据在共享的响应式状态中协调，本地持久化仍复用现有名言管理器。名言管理与共享布局不通过直接组件通信同步，也不引入服务端 API 或数据格式变更。
- 列表发生增、改、删或恢复默认时，当前批次保持不变；下一批从更新后的列表生成。
- 系统声明 `prefers-reduced-motion: reduce` 时隐藏弹幕，不显示静态替代文本。
- 关闭状态仅保存在运行中的前端状态里，可跨路由保持；页面刷新后恢复默认显示，不写入名言列表或本地持久化。
- 关闭控件使用已有 UI 库的图标能力并提供中文可访问名称。实现继续遵循既有前端依赖边界：视图与组件负责展示和交互，共享状态负责协调持久化和跨路由状态。

## 测试决策

- 以用户可观察行为为测试对象，不断言内部状态、定时器实现或随机算法细节。
- 使用现有 Playwright 浏览器烟测作为唯一新增测试缝隙，沿用 `market-smoke` 的模拟 API、访问路由和收集页面错误模式，不新增组件级测试框架。
- 桌面端测试应在至少两个受支持路由中确认弹幕存在、位于页头和内容区之间、普通区域不截获点击、关闭后跨路由保持隐藏且刷新后恢复。
- 浏览器测试应使用受控的名言列表，验证一批只包含 2 至 3 条不重复名言；列表不足三条时验证全部名言出现且不重复。
- 浏览器测试应确认保存、编辑、删除和恢复默认后的当前批次不突变，后续批次使用更新列表。
- 响应式测试应在最大宽度 768px 的视口验证弹幕和关闭按钮均隐藏。
- 辅助功能测试应模拟减少动态效果，验证弹幕隐藏；桌面端验证关闭控件可通过其中文可访问名称定位。
- 所有浏览器测试都必须收集页面错误并断言没有新增控制台或页面运行错误。

## 范围外内容

- 服务端同步、账户级名言、跨设备关闭偏好或任何新增 API。
- 名言分类、标签、搜索、排序、点赞或其他名言管理功能。
- 修改名言内容、作者字段、最大长度或现有 `localStorage` 数据格式。
- 移动端静态名言条、移动端关闭设置或移动端动画。
- 可由用户配置的播放速度、批次数量、颜色主题或弹幕位置。
- 多行、多轨道或同时飘过的名言展示。

## 补充说明

- 此规格与已验证的 OpenSpec 变更 `global-quote-barrage` 保持一致；后者是前端受支持行为的版本化来源。
- 该变更为局部、可回退的前端展示改动，不需要新增 ADR，也不需要配套服务端变更。
- 实施完成后应按仓库流程更新 OpenSpec 任务并在桌面端、移动端完成布局与控制台错误检查。
