# 配债详情导出

状态：ready-for-agent

本变更对应 `trading-toolkit-service/openspec/changes/placement-document-export`。权威的 Web 提案、增量规格、设计和任务清单位于 `openspec/changes/placement-document-export/`。

## 问题说明

配债工作区只在交互式界面中展示配债候选标的（Placement Candidate）的决策辅助数据。用户无法把单个候选标的的发行人条款、时间安排、成本计算、当前预期上市溢价假设、风险提示和配债来源信息保留或分享为一份持久记录。该功能必须保持规划观察与已确认可执行机会之间的界限。

## 方案

为每个可见配债候选标的增加直接 Markdown 导出操作。Web 从当前配债视图已加载的候选标的生成并下载一份配债详情导出文档。文档捕获点击时生效的假设，保留不可用和需复核的配债来源信息状态，不提供批量、ZIP、服务端导出、预览或确认流程。

## 用户故事

1. 作为配债研究者，我希望从桌面表格行下载一个候选标的详情，以便不打开弹窗就保存当前决策记录。
2. 作为移动端配债研究者，我希望每张候选卡片都有同样的导出操作，以便在小屏幕上也能导出。
3. 作为比较候选标的的研究者，我希望每个候选标的对应一个 Markdown 文件，而不是合并报告，以便单独归档或分享。
4. 作为研究者，我希望导出文件名包含正股名称、正股代码和导出日期，以便在应用外识别下载文件。
5. 作为会调整预期上市溢价假设的研究者，我希望文档保留选定假设及其派生指标，以便导出内容与评估结果一致。
6. 作为规划所需资金的研究者，我希望文档包含 1 至 5 手成本计算，以便离线比较资金需求。
7. 作为复核观察结果的研究者，我希望文档明确配债不是确认收益，避免将规划数据误解为可执行保证。
8. 作为检查候选标的依据的研究者，我希望服务端提供时文档包含配债来源信息、公告元数据和链接，以便追溯事实来源。
9. 作为处理不完整数据的研究者，我希望不可用字段仍明确显示为不可用，避免文档杜撰来源信息或计算结果。
10. 作为检查未核验或需复核候选标的的研究者，我希望仍可导出且清楚标明状态，以便留下后续跟进记录。
11. 作为仍使用旧服务响应的用户，我希望配债列表和单项导出继续工作，即使逐候选标的来源信息尚不可用。

## 实施决策

- Web 从规范化的配债候选标的、点击时生效的预期上市溢价假设、现有成本计算和可用快照元数据在客户端生成 Markdown。
- 一份配债详情导出文档只包含一个配债详情，并在明确逐项操作后立即下载。
- 文件名为 `配债详情-{正股名称}（{正股代码}）-{导出日期}.md`；清洗只替换文件系统不允许的字符。
- 桌面配债表格的每行提供专用导出操作，每张移动端卡片提供等价操作。激活操作不会打开现有详情弹窗。
- 文档包含完整候选详情、1 至 5 手成本表、当前假设及派生指标、固定的规划观察提示、快照新鲜度以及核验或复核状态。
- 同名服务端变更为每个待发项增加可选的 `placement_provenance`（配债来源信息）。它包含参与资格、登记日、配售条款、缴款时点、公告日期和 URL、核验时间以及需复核状态。
- 继续接受旧待发数组和 `{ items, meta }` 响应形式。旧或不完整的配债来源信息以不可用显示，Web 不推断缺失信息，也不读取 `placement_evidence` 或裸 `provenance`。
- 未核验和需复核候选标的仍可导出。文档必须明确配债来源信息状态，不得表示为已确认可执行机会。

## 测试决策

- 最高风险行为边界是配债工作区的显式逐项导出操作。浏览器验证必须断言一次操作只下载一个 Markdown 文件、文件名符合约定，并且操作不会打开候选标的详情弹窗。
- 聚焦文档渲染验证必须覆盖当前假设、完整与不可用的配债来源信息、未核验或需复核状态、固定提示和 1 至 5 手成本表。
- 浏览器验证必须覆盖桌面表格与移动卡片入口，以及增强和旧式待发响应形式。
- 既有基于 Playwright 的配债验证是浏览器配置、页面跳转、响应式视口和下载断言的参考实现。
- 完成前必须执行构建、格式检查和 OpenSpec 校验。

## 非目标

- 多选、批量下载、ZIP 打包、导出历史、浏览器持久化和服务端文件生成。
- 新增市场数据源、配债来源信息排序规则、发行人核验工作流或投资执行行为。
- 将陈旧、不可用、推断、未核验或需复核的配债来源信息表示为实时已核验事实。

## 补充说明

- 服务端和 Web 变更必须使用相同的 `placement-document-export` 名称，并统一使用 `placement_provenance` 作为可选配债来源信息字段。
- 已有的配债快照持久化变更保持独立；本变更在可用时消费其元数据，不新增快照存储。
